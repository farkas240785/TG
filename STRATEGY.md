# 🛡️ СТРАТЕГИЯ БЫСТРОГО ВОССТАНОВЛЕНИЯ САЙТА

## 📋 Обзор

Этот документ описывает комплексную стратегию резервного копирования и быстрого восстановления сайта "Тигель & Горн".

**Время восстановления:**
- 🟢 **Минимальное:** 5 минут (потеря node_modules/dist)
- 🟡 **Среднее:** 30 минут (потеря исходного кода)
- 🔴 **Максимальное:** 2 часа (полная потеря + настройка)

---

## 🎯 Компоненты системы восстановления

### 1. 📋 BACKUP_MANIFEST.md
**Назначение:** Полный манифест проекта  
**Содержимое:**
- Список всех 40 файлов
- Структура проекта
- Ключевые данные (реквизиты, аккаунты, каталог)
- Дизайн-система (цвета, шрифты)
- Зависимости и команды

**Когда использовать:**
- При проверке наличия файлов
- При восстановлении отдельных файлов
- При аудите проекта

---

### 2. 🔍 check-integrity.sh
**Назначение:** Автоматическая проверка целостности  
**Функции:**
- Проверка наличия всех 40 файлов
- Проверка структуры директорий
- Проверка node_modules и dist
- Вывод отчёта с ошибками и предупреждениями

**Как использовать:**
```bash

```

**Когда запускать:**
- Перед началом работы
- После внесения изменений
- При подозрении на потерю файлов
- По расписанию (ежедневно)

---

### 3. 📚 RESTORATION_GUIDE.md
**Назначение:** Пошаговое руководство по восстановлению  
**Содержимое:**
- 3 сценария восстановления (быстрый, средний, полный)
- Проверка целостности
- Восстановление зависимостей
- Восстановление исходного кода
- Проверка сборки
- Тестирование
- Частые проблемы и решения

**Когда использовать:**
- При потере файлов
- При ошибках сборки
- При проблемах с запуском

---

### 4. 🔄 restore.sh
**Назначение:** Автоматическое восстановление структуры  
**Функции:**
- Создание всех директорий
- Создание файлов-заглушек
- Создание конфигурационных файлов
- Вывод инструкций по дальнейшему восстановлению

**Как использовать:**
```bash
chmod +x restore.sh
./restore.sh
```

**Когда использовать:**
- При полной потере структуры проекта
- При создании нового проекта с нуля
- При переносе на другой компьютер

---

### 5. 💾 backup.sh
**Назначение:** Создание резервных копий  
**Функции:**
- Копирование всех файлов проекта
- Создание метаданных бэкапа
- Создание архива .tar.gz
- Расчёт контрольных сумм

**Как использовать:**
```bash
chmod +x backup.sh
./backup.sh
```

**Когда использовать:**
- Ежедневно перед началом работы
- После значимых изменений
- Перед деплоем
- По расписанию (cron)

## 🔄 Стратегия резервного копирования

### Частота создания бэкапов

| Тип бэкапа | Частота | Хранение |
|------------|---------|----------|
| **Ежедневный** | Каждый день | 7 дней |
| **Еженедельный** | Каждое воскресенье | 4 недели |
| **Ежемесячный** | 1 число месяца | 12 месяцев |
| **Перед релизом** | По необходимости | Постоянно |

### Места хранения

#### 1. Локальное хранилище
```
project/
└── backups/
    ├── backup_20260120_120000.tar.gz
    ├── backup_20260119_120000.tar.gz
    └── ...
```

#### 2. Облачное хранилище
- **Google Drive:** `/Projects/Тигель_и_Горн/backups/`
- **Dropbox:** `/Projects/Тигель_и_Горн/backups/`
- **Яндекс.Диск:** `/Projects/Тигель_и_Горн/backups/`

#### 3. Git (рекомендуется)
```bash
# Создать тег для важной версии
git tag -a v2.1 -m "Версия 2.1 - Полная функциональность"
git push origin v2.1

# Или создать отдельную ветку для бэкапа
git checkout -b backup/2026-01-20
git add .
git commit -m "Резервная копия 2026-01-20"
git push origin backup/2026-01-20
```

#### 4. Внешний носитель
- USB-флешка
- Внешний HDD
- Сетевое хранилище (NAS)

## 🚀 Сценарии восстановления

### Сценарий 1: Потеря node_modules (5 минут)

**Симптомы:**
- Ошибки "Module not found"
- Не запускается dev сервер

**Решение:**
```bash
npm install
npm run build
npm run dev
```

---

### Сценарий 2: Потеря dist/ (5 минут)

**Симптомы:**
- Отсутствует папка dist
- Не работает production сборка

**Решение:**
```bash
npm run build
```

---

### Сценарий 3: Потеря отдельных файлов (15 минут)

**Симптомы:**
- Ошибки компиляции
- Отсутствуют некоторые страницы

**Решение:**
```bash
# 1. Проверить целостность
./check-integrity.sh

# 2. Восстановить из бэкапа
tar -xzf backup_20260120_120000.tar.gz
cp -r backup_20260120_120000/src/* src/

# 3. Пересобрать
npm run build
```

---

### Сценарий 4: Потеря всего исходного кода (30 минут)

**Симптомы:**
- Пустая папка src/
- Отсутствуют все файлы проекта

**Решение:**
```bash
# 1. Восстановить структуру
./restore.sh

# 2. Восстановить содержимое из бэкапа
tar -xzf backup_20260120_120000.tar.gz
cp -r backup_20260120_120000/* .

# 3. Установить зависимости
npm install

# 4. Собрать проект
npm run build

# 5. Проверить
./check-integrity.sh
```

---

### Сценарий 5: Полная потеря + новый компьютер (2 часа)

**Симптомы:**
- Нет доступа к предыдущему компьютеру
- Нет локальных бэкапов

**Решение:**
```bash
# 1. Клонировать из Git (если есть)
git clone <repository-url>
cd project

# 2. Или восстановить структуру
./restore.sh

# 3. Восстановить из облачного бэкапа
# Скачать backup_*.tar.gz из Google Drive/Dropbox
tar -xzf backup_20260120_120000.tar.gz
cp -r backup_20260120_120000/* .

# 4. Установить зависимости
npm install

# 5. Собрать и проверить
npm run build
./check-integrity.sh

# 6. Следовать RESTORATION_GUIDE.md
```

## 📅 Автоматизация резервного копирования

### Cron job (Linux/Mac)

```bash
# Открыть crontab
crontab -e

# Добавить задачу (ежедневно в 23:00)
0 23 * * * /path/to/project/backup.sh >> /path/to/project/backups/backup.log 2>&1
```

### Windows Task Scheduler

1. Открыть Task Scheduler
2. Создать задачу
3. Триггер: Ежедневно в 23:00
4. Действие: Запустить программу
5. Программа: `bash.exe`
6. Аргументы: `/path/to/backup.sh`

### GitHub Actions (CI/CD)

```yaml
# .github/workflows/backup.yml
name: Daily Backup

on:
  schedule:
    - cron: '0 23 * * *'  # Ежедневно в 23:00 UTC
  workflow_dispatch:  # Ручной запуск

jobs:
  backup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Create backup
        run: |
          chmod +x backup.sh
          ./backup.sh
          
      - name: Upload backup
        uses: actions/upload-artifact@v3
        with:
          name: backup-${{ github.run_id }}
          path: backups/
```
